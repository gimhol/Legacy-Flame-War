# base/Ticker + base/FPS
#
# 假宿主：`clk set/adv/hidden/pend`（`Ditto.Clock` 槽）、`fire`（发一次待发回调 ——
# Ticker 同时只挂一个：先看 Timeout 再看 Clock）。`tk new` 会把两个待发队列丢掉 ⇒
# 每段用例都能独立读。
# 两侧都把 `CLK add/del`、`TOUT add/del`（含 delay 的位模式）、`FIRE`、`STEP <序号> <bits(dt)>`
# 打进日志 —— 「走 Timeout 还是走 Clock」「delay 是多少」「这一步真的步进了吗」都在里面。
#
# `tk new <step_ms>` / `tk stepms` / `tk spent <ms>`（`on_step` 里假时钟前进多少，驱动 cost 的
# EMA）/ 六个旋钮 / start|stop|pause|resume|resync <0|1> / dump；
# `fps new [<retention>]|update <dt>|reset|dump`。

# ---- S1 启动：delay(16) > sleep_threshold(2) 且未 hidden ⇒ 走 Timeout -------------
clk set 1000
tk new 16
tk start
tk resume
tk dump
clk pend

# ---- S2 到点：t0 == deadline ⇒ 步进（dt = 16）-----------------------------------
clk set 1016
fire
tk dump
clk pend

# ---- S3 早触发：t0 < deadline ⇒ 不步进；delay == sleep_threshold ⇒ 改走 Clock -----
clk set 1030
fire
tk dump
clk pend

# ---- S4 由 Clock 唤起：到点步进（dt = 16）--------------------------------------
clk set 1032
fire
tk dump
clk pend

# ---- S5 hidden / 未 hidden 的调度分支（delay 都是 16）---------------------------
clk hidden 1
tk resync 0
tk dump
clk pend
clk hidden 0
tk resync 0
tk dump
clk pend

# ---- S6.5 重入钩子：`on_step` 里回调 Ticker 自己（`_schedule` 守卫的三个因子）---
# `_pending` 在 `_tick` 开头就被清了 ⇒ 此刻 `resume`/`pause`/`stop` 都必须被守卫拦住，
# 各自不能再排一个回调（少了守卫就会多出一行 `TOUT add` / `CLK add`）。
# 每段都 `clk set` 到新起点再 `tk new`（`_deadline = start + step_ms` 是 `start` 算的）。
clk set 4700
tk new 16
tk start
tk inside resume
clk set 4716
fire
tk dump
clk pend
clk set 4800
tk new 16
tk start
tk inside pause
clk set 4816
fire
tk dump
clk pend
clk set 4900
tk new 16
tk start
tk inside stop
clk set 4916
fire
tk dump
clk pend
