# 数据包读取与压缩方法

宿主（Godot 与 headless）读数据包时只区分两件事：**能不能惰性读**、**压缩方法认不认**。

相关：[打包](packaging.md) · [模组](mods.md)

## 惰性读取

打开 `.zip` 只读尾部 EOCD（最多 64KB）+ 中央目录，条目留到真正用到时才 seek 到本地头再
解压，解压结果不驻留：

| 项 | 开销 |
|---|---|
| 索引（`data.zip` 633 条） | 42 KB |
| 索引（`prel.zip` 180 条） | 12 KB |
| 整包 | 0（不进内存） |
| 单个条目 | 读取那一刻的临时缓冲，交给上层后释放 |

所以 `resources/*.zip` 可以直接发 zip，不需要 `--unpack`。上层（纹理 / 音频 / JSON）各自有
缓存，同一条目实际只读一次。

**能惰性的前提**：

| 条件 | 不满足时 |
|---|---|
| 非 ZIP64（条目数 < 65535、单条目 < 4GB、偏移 < 4GB、文件 < 4GB） | `zip64 is not supported` |
| 尾部 64KB 内找得到 EOCD（注释 ≤ 65535B） | `end of central directory not found` |
| 中央目录可解析且条数与 EOCD 一致 | `bad central directory record` / `entry count mismatch` |
| 数据源可随机访问 | 内存源也支持（只是嵌套 zip 走解压缓存，见下） |
| 条目压缩方法内建支持（见下节） | 走解压缓存 |

## 压缩方法

内建解压器只支持 **stored(0)** 与 **deflate(8)**，这两种完全惰性、不落地。

其它方法会在**第一次打开时把整包解压到临时缓存**，之后按需读文件：

```
%TEMP%\lfw-zip-cache\<指纹>\      解压结果 + .lfw-cache 清单
```

| 行为 | 说明 |
|---|---|
| 指纹 | 来源路径 + 文件大小 + 修改时间 + 条目数与各条目压缩方法；同一个包从路径或内存打开共用一份 |
| 复用 | 指纹一致且每个文件的 **大小 + CRC-32** 都对得上才复用，**不会重复解压** |
| 完整性 | 解压后逐条校验 `CRC-32` 与解压后大小，任一条不符就整份重来；清单原子写入（先解到 `.tmp<pid>`，校验通过再改名） |
| 安全 | 条目名含 `..` / 绝对路径 / 盘符的直接拒绝，不会解压到缓存目录之外（反斜杠归一化成 `/`） |
| 并发 | 解压目录带 pid，改名失败时若目标已存在且清单可用就直接采用 |

解压工具链（按顺序尝试，失败自动换下一个）：

1. `LFW_TAR` 环境变量（自定义工具，按 `tar -xf <zip> -C <dir>` 调用）
2. 系统 `bsdtar`：`%SystemRoot%\System32\tar.exe` —— 支持 bzip2 / lzma / zstd
3. `7-Zip`（`Program Files\7-Zip\7z.exe`）—— 补 deflate64 / zstd-in-zip

都找不到就报错并跳过该包。

## 实测

| 包 | 压缩方法 | 结果 |
|---|---|---|
| `prel.zip` | lzma / bzip2 / deflate64 | 与 deflate 版 `digest` 完全一致 |
| `data.zip`（31.4MB） | lzma | 一致；首次 ~4.0s，缓存复用 ~2.4s（基线 ~2.0s） |
| 缓存被改坏 | — | CRC 不符 → 自动重解压恢复 |
| 恶意条目 `../escaped.txt` | — | 拒绝，缓存目录外不落文件 |

## 压缩率参考

惰性读取不影响压缩率（仍是逐条 deflate），与固体压缩（solid 7z/xz）的差距来自内容构成：

| 包 | 逐条 deflate（现状） | deflate -9 | 固体 xz（不能惰性） |
|---|---|---|---|
| `data.zip` | 31.7 MB | 31.5 MB | 31.1 MB |

数据包解包后 37.5MB 里 49% 是 `.mp3`、33% 是 `.png`（都已压缩），只有 16% 的 `.json5` 能压。
想再小只能换逐条 LZMA/zstd（本页的解压缓存已经支持读，但打包脚本仍输出 deflate）。
